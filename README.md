# ai-task-economy

AI 应用商业化的任务驱动付费与 Token 经济技能：AI 公司卖的不是软件许可，而是模型/工具/智能体持续完成的业务任务，收入随 Token 消耗增长——先盘任务量（频次×版本数×市场数）、统一计量账户、SOP 单链路数据回流、按单位指标验收、跑通一条再横向扩。

一句话：**模型越强越不稀缺，真正的增量在企业把多少「每周重复发生的工作」交给系统，而不在模型榜单。**

## 经济模型底座

- 三种付费模式：许可（封顶）→ 任务驱动（随业务扩张）→ Token 消耗（随调用扩张）
- 任务量公式：频次 × 版本数 × 市场数，至少两个因子显著 >1 才建管线
- 统一计量（KP 钱包同构）：账户+额度+成本归属，"值不值"变可观测
- 路由层被定价：Stripe 超 70 亿美元收购 OpenRouter（B 轮 13 亿，5.4 倍溢价）——编排/路由层升值，入口层贬值
- 模型与入口分离：18 款视频生成产品流量环比 -4.3%（Dreamina -30.3%、Wan AI -20.4%）
- 客户实证：茶饮 20→80 条/日、复用率 +50%、点击成本 -18%；东南亚 3C 50→500 条/日、转化 1.2%→6.8%

## 解决什么

| 痛点 | 本技能的做法 |
|---|---|
| 不知道哪个环节值得 AI 化 | 任务量公式盘账：量撑不起持续消耗别建管线 |
| AI 花费说不清值不值 | 统一账户+月度额度+成本归属台账 |
| AI 只做单点提效 | SOP 单链路+效果数据回流下一轮生产 |
| 用产出条数当成功 | 单位指标验收（单条成本/复用率/点击成本/转化率）+基线+阈值 |
| 感觉不错就横向扩 | 第一链路 ≥2 周台账+指标稳定才扩第二商品 |
| 评估 AI 公司被自述数字带跑 | 数据分层（自述/预期/第三方/转述），决策只用第三方+独立核实 |
| 模型变强就判断工具没价值 | 分清入口（贬值）与任务（升值） |

## 安装

复制本目录到 `~/.agents/skills/`（或你的 Skill 加载路径）即可。

## 自检

```bash
python scripts/validate.py tests/sample_good.json   # 必须 exit 0
python scripts/validate.py tests/sample_bad.json    # 必须 exit 1

# 一行自验（正反向 + 退出码全覆盖，零依赖）
python tests/test_validate.py
```
